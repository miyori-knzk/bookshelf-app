# 例外方針

エラーや例外が起きたときに、どう扱い、利用者に何を返すかをまとめたもの。範囲は基本機能のみ。
入力チェックの内容は `docs/validation-rules.md`、画面に出すメッセージは `docs/screen-transitions.md` の「処理後の移動先」を参照。

## 方針

| No. | 方針                                                                                                   | 理由 |
| --- | ------------------------------------------------------------------------------------------------------ | ---- |
| 1   | コントローラーでは例外を捕まえない（`try`〜`catch` を書かない）。Laravel の例外ハンドラー（`app/Exceptions/Handler.php`）に任せる | 要件「コントローラーの責務」（受付と返却に専念）。扱いを 1 か所にまとめるため |
| 2   | 入力チェックで防げるものは入力チェックで止め、DB のエラーに頼らない                                    | DB のエラーは 500 になり、利用者に何を直せばよいか伝わらない（`docs/table-definitions.md`「strict モード」） |
| 3   | 業務ルールで止めるもの（書籍が紐付いたジャンルの削除）は、例外にせず、確かめてからメッセージを付けて戻す | 利用者が直せる失敗のため（Q-17） |
| 4   | 利用者にはエラーの詳細（SQL・ファイル名・スタックトレース）を見せない。本番では `APP_DEBUG=false` にする | 中の作りが外に漏れないため |
| 5   | 予期しない例外（500）はログに残す。入力エラー・未ログイン・403・404 などの想定内のものは残さない         | Laravel の標準の動き。ログを、直すべきものだけにするため |
| 6   | 公開API は、どのエラーも JSON で返す                                                                   | 外部アプリは HTML を読めないため（下の「公開API は必ず JSON で返す」） |

## Web の扱い

| 場合                                      | 例外・仕組み                     | ステータス | 利用者に見える動き                                         | 確認事項 |
| ----------------------------------------- | -------------------------------- | ---------- | ---------------------------------------------------------- | -------- |
| 入力がルールに合わない                    | `ValidationException`            | 302        | 入力した画面へ戻り、入力値とエラーメッセージを表示         | Q-11 など |
| ログインが必要な画面・操作を、ゲストが使った | `AuthenticationException`       | 302        | ログイン画面へ移動。GET なら、ログイン後に元の画面へ戻る   | Q-10     |
| ログイン中に、ログイン・会員登録の画面を開いた | `guest` ミドルウェア（例外ではない） | 302   | 書籍一覧へ移動                                             | Q-08     |
| 作成者・投稿者ではない人が、編集・更新・削除をした | `AuthorizationException`  | 403        | Laravel 標準のエラー画面                                   | Q-47     |
| 存在しない ID・URL を開いた               | `ModelNotFoundException`・`NotFoundHttpException` | 404 | Laravel 標準のエラー画面                         | Q-47     |
| メソッドが違う（POST だけのルート `/books/{book}/favorites` を、URL を直接入力して GET で開いた など） | `MethodNotAllowedHttpException` | 405 | Laravel 標準のエラー画面                    | －       |
| フォームを開いたまま時間がたち、セッションが切れてから送信した | `TokenMismatchException` | 419  | Laravel 標準のエラー画面（Page Expired）。入力した内容は消える | －       |
| 書籍が紐付いているジャンルを削除しようとした | 例外ではない（削除前に確かめる） | 302      | ジャンル一覧へ戻り、エラーメッセージを表示                 | Q-17     |
| ログインで、メールアドレスとパスワードが合わない | Fortify の `ValidationException` | 302  | ログイン画面へ戻り、メールアドレス欄にエラー（`auth.failed`） | Q-42     |
| ログインの回数が上限を超えた              | `ThrottleRequestsException`      | 429        | Laravel 標準のエラー画面（英語の「Too Many Requests」）。ログイン画面へは利用者が自分で戻る | Q-60     |
| DB のエラー・そのほか予期しない例外       | `QueryException` など            | 500        | Laravel 標準のエラー画面                                   | －       |

- エラー画面のビュー（`resources/views/errors/`）は無いため、403・404・405・419・500 は Laravel 標準の画面（英語）になる（Q-47）。
- 未ログインで、作成者だけの画面（書籍編集など）を開いたときは、403 ではなくログイン画面へ移動する。`auth` ミドルウェアが、Policy より先に止めるため。

## 公開API の扱い

### 公開API は必ず JSON で返す

Laravel は、リクエストに `Accept: application/json` が無いと、エラーを HTML の画面やリダイレクトで返す。外部アプリが `Accept` を付け忘れても JSON で返すよう、例外ハンドラーで `/api/` から始まる URL は必ず JSON にする（`shouldRenderJsonWhen()`）。

### ステータスごとの返し方

| 場合                                   | 例外                                | ステータス | `message`（案）                                       |
| -------------------------------------- | ----------------------------------- | ---------- | ----------------------------------------------------- |
| 入力がルールに合わない                 | `ValidationException`               | 422        | 最初のエラーのメッセージ（`errors` に項目ごとのメッセージ）。`docs/api-spec.md`「422 の例」 |
| その ID の書籍が無い                   | `ModelNotFoundException`            | 404        | 書籍が見つかりません。                                |
| 無いパス                               | `NotFoundHttpException`             | 404        | 指定されたURLは存在しません。                         |
| メソッドが違う                         | `MethodNotAllowedHttpException`     | 405        | このメソッドには対応していません。                    |
| 回数の制限を超えた                     | `ThrottleRequestsException`         | 429        | リクエストが多すぎます。しばらくしてからもう一度お試しください。 |
| DB のエラー・そのほか予期しない例外    | `QueryException` など               | 500        | サーバーでエラーが発生しました。                      |

- 422 以外の文言は、Laravel 標準のままだと英語になる。また 404 は、標準のままだとモデルのクラス名（`App\Models\Book`）が `message` に入る。そのため、例外ハンドラーで、`/api/` の URL のときだけ上の文言に置き換える（Q-53）。
- 公開API には認証が無いため、401・403 は基本機能では返さない。★応用機能で Sanctum を入れると、401（トークンが無い・正しくない）と 403（作成者ではない）が増える。

## トランザクションと例外

| 処理                           | 例外が起きたとき                                                         | 確認事項 |
| ------------------------------ | ------------------------------------------------------------------------ | -------- |
| 書籍の登録・更新（Web・API）   | `DB::transaction()` が、途中まで書いた `books`・`book_genre` をロールバックし、例外をそのまま投げる（500） | Q-05     |
| 書籍・レビューの削除           | SQL 1 文。関連する行は DB の cascade で同時に消えるため、途中で止まることは無い | Q-05・Q-12 |

`DB::transaction()` の中でも例外を捕まえない。捕まえるとロールバックされず、書籍だけが残る。

## めったに起きない DB エラー

入力チェックや削除前の確認をすり抜けて、DB の制約で止まる場合。どれも 2 人以上がほぼ同時に操作したときにだけ起きる。特別な扱いはせず、500 にする。

| 場合                                                             | 止まる制約                    | 機能             |
| ---------------------------------------------------------------- | ----------------------------- | ---------------- |
| 同じ ISBN の書籍を、2 人がほぼ同時に登録した                     | `books.isbn` のユニーク制約   | F-03・F-04・F-23・F-24 |
| 同じジャンル名を、2 人がほぼ同時に登録した                       | `genres.name` のユニーク制約  | F-08・F-09       |
| 削除前の確認の後、削除までの間に、そのジャンルが書籍に紐付けられた | `book_genre.genre_id` の外部キー | F-10          |
| ハート・いいねのボタンを、すばやく 2 回押した                    | `favorites`・`review_likes` の主キー | F-14・F-15 |

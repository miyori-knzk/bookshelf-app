BookShelf 書籍レビューアプリ

## システム概要

本システムは、書籍レビューアプリケーション「BookShelf」です。
ユーザーは書籍を登録・閲覧し、レビューの投稿やお気に入り登録ができます。
ジャンルによる分類やレビューへのいいね機能、平均評価に基づくランキング機能も備えています。
外部アプリケーション向けの公開API（JSON）も提供します。

## アーキテクチャ

本プロジェクトのアーキテクチャについて（Traditional Web + 公開API）

本アプリでは、Traditional Web（Blade + セッション認証）アーキテクチャを採用します。加えて、外部アプリケーション向けの公開API（JSON）も基本機能として実装します。

### Webブラウザ向け機能（Traditional Web）

Bladeテンプレートを使用し、セッション認証（Cookie）で動作する従来のWebアプリケーション機能。
`routes/web.php` と通常のコントローラー（`app/Http/Controllers/`）を使用します。

### 外部アプリケーション向け公開API（JSON）

`routes/api.php` と `Api\V1` 名前空間のコントローラー（`app/Http/Controllers/Api/V1/`）を使用します。基本機能では認証なしの CRUD として実装し、応用機能で Sanctum によるトークン認証を後付けします。

## バリデーション方針

### 書籍登録

- タイトル・著者名等の必須項目を検証すること
- ISBNの桁数と一意性を担保すること
- 出版日が有効な日付であること
- ジャンルは1つ以上選択されていること
- 画像URLが指定された場合はURL形式であること

### 書籍編集

- 書籍登録と同等のバリデーションを行うこと
- ISBNの一意性チェックでは自身のレコードを除外すること

### 公開API 書籍一覧

- 検索パラメータ（キーワード、ジャンルID、ページ番号、ページあたり件数）をバリデーションすること

### 公開API 書籍登録

- Web版の書籍登録と同等のバリデーションに加え、登録者IDの妥当性を検証すること
- 日本語のエラーメッセージを定義すること

### 公開API 書籍編集

- 公開API書籍登録と同等のバリデーションを行うこと
- ISBNの一意性チェックでは自身のレコードを除外すること

### レビュー投稿

- 評価値の範囲を検証すること

### レビュー編集

- レビュー投稿と同等のバリデーションを行うこと

### ジャンル登録

- ジャンル名の必須チェックと一意性を検証すること

### ジャンル編集

- ジャンル登録と同等のバリデーションを行うこと
- 一意性チェックでは自身のレコードを除外すること

### 会員登録

- 名前・メールアドレス・パスワードを検証すること

### ログイン

- メールアドレスとパスワードの必須チェックを行うこと

### バリデーションメッセージ

- 全FormRequestに messages() メソッドを実装し、日本語のバリデーションメッセージを定義すること
- 具体的な文言は自分で設計すること

### ★ 書籍登録・編集

- ★ 応用機能では一部の必須項目がnullable（任意入力）に変更される
- 具体的な変更対象は自分で検討し設計すること

### ★ 公開API 書籍登録・編集

- ★ Sanctum 認証導入に伴い、登録者IDのバリデーションルールを見直すこと

### ★ 読書計画作成・編集

- ★ 計画作成・編集にバリデーションを実装すること
- ルール詳細・重複制御・編集制限・エラーメッセージは自分で検討し設計すること
- FormRequestクラスに分離すること

## 開発ルール

### 命名規則

- Laravelの標準命名規則（PSR-12準拠）に従うこと
    - 変数/メソッド: camelCase
    - クラス: PascalCase
    - DBテーブル: snake_case（複数形）
    - DBカラム: snake_case（単数形）
    - モデル名：アッパーキャメル
    - コントローラー名：アッパーキャメル
    - フォームリクエスト名：アッパーキャメル
    - マイグレーションファイル名：スネークケース
    - シーディングファイル名：アッパーキャメル
- 変数名やメソッド名に a, x など意味のない命名をしないこと
- ローマ字（例: okyakusama）など英単語ではないもので命名しないこと

### コードフォーマット

- コミット前に、`vendor/bin/pint` を実行し、整形されたコードをコミットする

### 型宣言

- すべてのコントローラ、モデル、FormRequest、Policyのメソッドに、引数と戻り値の型を明示的に宣言する
    - 例: `public function index(): View`
- モデルのリレーションメソッドには `HasMany`, `BelongsTo`, `BelongsToMany` などの具体的な戻り値型を宣言する

### PHPDoc

- 主要なメソッドには、処理内容、引数、戻り値を説明するPHPDocコメントを記述する

### コントローラーの責務

- コントローラーはリクエストの受付とレスポンスの返却に専念させる
- 複雑なビジネスロジックはモデルやサービスクラス（任意）に記述する

### FormRequest

- バリデーションロジックは必ずFormRequestクラスに分離する

### Policy

- 認可処理（リソースの所有者チェック等）は必ずPolicyクラスで実装する
- コントローラーで `$this->authorize()` を使用してPolicyを適用する

### Eloquent ORM

- DB操作にはEloquentを最大限活用し、クエリビルダや生SQLは原則使用しない
- N+1問題を避けるため、`with()` メソッドによるEager Loadingを適切に使用する

### Collectionメソッド活用

- foreach などの手続き的なループを避け、`map`, `filter`, `groupBy`, `flatMap` などのCollectionメソッドを積極的に活用する
- 宣言的で可読性の高いコードを記述すること
- 特にマイ読書レポート機能でこれを徹底する

### 設定のハードコーディング禁止

- DB接続情報やAPIキーなどの設定値は、必ず `.env` ファイルで管理する
- コード内に直接設定値を書き込まない

### Git運用

- コミットメッセージは「何をしたか」が明確にわかるように記述する
    - 例: `feat: 書籍一覧表示を実装`
- **【重要】機能ごとにブランチを作成し、mainブランチにマージする**

### 目標

- 応用機能を含むテストカバレッジは 80% 以上を目標とする（基本は60％）
- `sail artisan test --coverage` で確認できる

## 機能要件の使用技術を遵守しているか

認証やバリデーションなど、指定した技術以外で実装されていないか

### 認証（Laravel Fortify）

- 認証機能は Laravel Fortify を使用して実装する

### Sanctum APIトークン認証

- 公開API の書き込み系エンドポイント（POST/PUT/DELETE）には Laravel Sanctum によるトークン認証を導入する
- `auth:sanctum` ミドルウェアで認証必須化し、BookPolicy で書籍所有者のみ更新・削除できるよう認可する

### 外部API連携

- 外部APIとの通信には、Laravel標準のHTTPクライアント (`Illuminate\Support\Facades\Http`) を使用する

### Schedule + Console Command

- 応用機能で必要となるバッチ処理は Laravel の Schedule + Console Command を使用して実装する

### Database Transaction

- 複数の SQL 文を 1 単位で扱う処理（例: あるレコード削除時に関連レコードも同時に削除する処理）で `DB::transaction()` を使用して原子化する

### Notification facade（DatabaseChannel）

- 通知機能は Laravel 標準の Notification facade を使用し、DatabaseChannel に保存する

### PHP Enum + Eloquent cast

- 限定された値の集合は PHP 8.1+ ネイティブ Enum で定義し、Eloquent の `casts()` でカラムに紐付ける

# 画面項目定義

画面に出す項目を、`resources/views/` 配下のビュー（以下「ビュー」）をもとに定義したもの。
画面 ID は `docs/screen-list.md` の画面一覧と同じ。範囲は基本機能のみ。
入力チェックとエラーメッセージは `docs/screen-input-checks.md` にまとめている。

## 対象にした画面

| 画面ID        | 画面名              | 対象にした理由                                                                                                       |
| ------------- | ------------------- | -------------------------------------------------------------------------------------------------------------------- |
| SC-03・SC-04  | 書籍登録・書籍編集  | 入力項目がいちばん多く（7 項目）、必須・任意・初期値・ジャンルの選択状態など、決めることが多い。2 画面で同じフォーム（`books/_form.blade.php`）を使うため、1 つの定義で 2 画面ぶんになる |
| SC-02         | 書籍詳細            | 表示項目と操作がいちばん多い。ログイン状態・作成者・投稿者・お気に入りやいいねの状態で表示が変わり、ビューを読むだけでは出し分けの全体がつかみにくい |

### 対象にしなかった画面

| 画面ID                    | 対象にしなかった理由                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------ |
| SC-07・SC-08・SC-09・SC-12・SC-13 | 入力項目が 1〜4 個で、表示の出し分けも無い。入力項目は `docs/screen-input-checks.md` に画面ごとに載せているので、それで足りる |
| SC-01・SC-05・SC-06・SC-10・SC-11 | 一覧画面で、同じ形の行（カード）を並べるだけ。表示内容は `docs/screen-list.md` の「主な表示内容・操作」で足りる。書籍カードの項目は SC-02 の書籍情報と同じデータを使う |

## 表の見かた

| 列         | 内容                                                                     |
| ---------- | ------------------------------------------------------------------------ |
| 種類       | 表示・入力・ボタン・リンクのどれか                                       |
| 入力名     | フォームで送る名前（`name` 属性）                                        |
| 形式       | 入力欄の種類（`type` 属性など）                                          |
| 必須       | 画面に必須マーク（*）があるもの。チェックの内容は `docs/screen-input-checks.md` |
| データ     | 表示・初期値に使うデータ                                                 |
| 表示条件   | 表示するときの条件。空欄は常に表示                                       |
| ビュー     | ビューの行番号                                                           |

## SC-03 書籍登録・SC-04 書籍編集

- ビュー：`books/create.blade.php`・`books/edit.blade.php`、入力欄は共通の `books/_form.blade.php`
- 送信先：登録は `books.store`（POST）、編集は `books.update`（PUT）
- フォームに `novalidate` が付いているため、ブラウザの入力チェックは働かない。チェックはすべてサーバー側で行う。

### 入力項目

| No. | 項目名   | 種類 | 入力名           | 形式                   | 必須 | 初期値（登録）             | 初期値（編集）               | 入力欄の補足（ビュー）                                       | ビュー（`_form`） |
| --- | -------- | ---- | ---------------- | ---------------------- | ---- | -------------------------- | ---------------------------- | ------------------------------------------------------------ | ----------------- |
| 1   | タイトル | 入力 | `title`          | `text`                 | ○    | 空                         | `$book->title`               | プレースホルダー「書籍のタイトルを入力」                     | 8〜18             |
| 2   | 著者     | 入力 | `author`         | `text`                 | ○    | 空                         | `$book->author`              | プレースホルダー「著者名を入力」                             | 21〜31            |
| 3   | ISBN-13  | 入力 | `isbn`           | `text`                 | ○    | 空                         | `$book->isbn`                | プレースホルダー「9784000000000」、説明「13桁のISBNコードを入力してください」 | 34〜44  |
| 4   | 出版日   | 入力 | `published_date` | `date`                 | ○    | 空                         | `$book->published_date`      | `YYYY-MM-DD` 形式。モデルでキャストしない（キャストすると時刻が付き、初期値が入らない） | 48〜56            |
| 5   | 説明     | 入力 | `description`    | `textarea`（4 行）     |      | 空                         | `$book->description`         | プレースホルダー「書籍の説明を入力（任意）」                 | 60〜69            |
| 6   | 画像URL  | 入力 | `image_url`      | `text`                 |      | 空                         | `$book->image_url`           | プレースホルダー「https://example.com/image.jpg」、説明「書籍の表紙画像のURLを入力してください（任意）」 | 73〜83 |
| 7   | ジャンル | 入力 | `genres[]`       | `checkbox`（複数選択） | ○    | どれも未選択               | その書籍に紐付いているジャンルを選択済み | 全ジャンルを並べる。値はジャンル ID、表示はジャンル名 | 87〜112           |

- 入力エラーで戻ったときは、どの項目も入力した値（`old()`）を初期値にする。
- ジャンルの並び順は、ビューに指定が無い（コントローラーで渡す `$genres` の順になる）。
- ジャンルが 1 件も無いときは、チェックボックスの代わりに「ジャンルが登録されていません。先にジャンルを登録してください。」を表示する（93 行目）。ジャンルは必須のため、このときは登録できない。

### ボタン・リンク

| No. | 項目名     | 種類   | 動作                                                         | ビュー                         |
| --- | ---------- | ------ | ------------------------------------------------------------ | ------------------------------ |
| 8   | キャンセル | リンク | 登録：SC-01 書籍一覧へ、編集：SC-02 書籍詳細へ               | `create` 16〜18、`edit` 17〜19 |
| 9   | 登録／更新 | ボタン | 登録は「登録」で `books.store` へ、編集は「更新」で `books.update` へ送信 | `create` 19〜21、`edit` 20〜22 |

### エラーの表示

各入力欄のすぐ下に、その項目のエラーを 1 件（最初の 1 件）表示する（`@error`）。ジャンルは、配列全体のエラー（`genres`）と各要素のエラー（`genres.*`）を別々に表示する。

## SC-02 書籍詳細

- ビュー：`books/show.blade.php`
- 未ログインでも開ける。ログイン状態・作成者かどうか・投稿者かどうかで、表示が変わる。

### 表示の出し分けに使う条件

| 記号 | 条件                           | ビューの書き方                                      |
| ---- | ------------------------------ | --------------------------------------------------- |
| 未   | 未ログイン                     | `@auth` の `@else`                                  |
| ロ   | ログイン中                     | `@auth`                                             |
| 作   | ログイン中で、書籍の作成者     | `@can('update', $book)`・`@can('delete', $book)`    |
| 投   | ログイン中で、レビューの投稿者 | `@can('update', $review)`・`@can('delete', $review)` |

## ビューが使うリレーション名

ビューは次のリレーションを、この名前で呼んでいる。ビューは変えないため、モデルのリレーションはこの名前で作る。

| モデル   | リレーション名 | 相手               | 使っているビュー                                                     |
| -------- | -------------- | ------------------ | -------------------------------------------------------------------- |
| `Book`   | `genres`       | `Genre`（多対多）  | `books/index`・`books/show`・`books/_form`・`genres/show`            |
| `Book`   | `reviews`      | `Review`（1 対多） | `books/show`                                                         |
| `Genre`  | `books`        | `Book`（多対多）   | `genres/index`（`books_count`。下の表）                              |
| `Review` | `user`         | `User`（多対 1）   | `books/show`（投稿者名）                                             |
| `Review` | `book`         | `Book`（多対 1）   | `reviews/edit`（書籍名、キャンセル先）                               |
| `Review` | `likedByUsers` | `User`（多対多）   | `books/show`（いいねの件数）                                         |
| `User`   | `favoriteBooks` | `Book`（多対多）  | `books/show`（お気に入り登録済みかの判定）                           |
| `User`   | `likedReviews` | `Review`（多対多） | `books/show`（いいね済みかの判定）                                   |

テーブルとのつながりは `docs/er-diagram.md` の「モデルのリレーション」を参照。

ビューは次の集計値も使う。コントローラーで、上のリレーション名を指定して作る。

| 値                   | 作り方                            | 使っているビュー                |
| -------------------- | --------------------------------- | ------------------------------- |
| `reviews_avg_rating` | `withAvg('reviews', 'rating')`    | `books/index`・`ranking/index`  |
| `reviews_count`      | `withCount('reviews')`            | `ranking/index`                 |
| `books_count`        | `withCount('books')`（`Genre`）   | `genres/index`                  |

一覧や詳細で、行ごとにリレーションを読み込むと N+1 問題になる。上のリレーションは、コントローラーで `with()` を使ってまとめて読み込む（要件「Eloquent ORM」）。

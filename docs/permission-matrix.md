# 権限マトリクス

機能（`docs/features.md` の F-xx）ごとに、利用者の区分ごとに使えるかどうかをまとめたもの。範囲は基本機能のみ。
URL・ミドルウェアは `docs/routing.md`、止められたときの動きは `docs/error-handling.md` を参照。

## 利用者の区分

| 区分   | 意味                                       |
| ------ | ------------------------------------------ |
| ゲスト | ログインしていない利用者                   |
| 会員   | ログインしている利用者（会員登録したユーザー） |

- 管理者などのロールは作らない（Q-33）。会員はみな同じ権限で、違いは「その書籍の作成者か」「そのレビューの投稿者か」だけ。
- 公開API（F-21〜F-25）は、基本機能では認証しない（要件「APIエンドポイント一覧」）。呼び出し元がログインしているかは見ないため、外部アプリからの呼び出しも、ゲストと同じ扱いになる。

## 表の見かた

| 記号 | 意味                                       |
| ---- | ------------------------------------------ |
| ○    | 使える                                     |
| △    | 条件を満たすときだけ使える（条件は表の下） |
| ×    | 使えない                                   |

### △の条件

| 記号 | 条件                                                         | 止める場所                              | 対象       |
| ---- | ------------------------------------------------------------ | --------------------------------------- | ---------- |
| △1   | その書籍の作成者（`books.user_id` がログイン中のユーザーの ID） | `BookPolicy` の `update`・`delete`      | F-04・F-05 |
| △2   | そのレビューの投稿者（`reviews.user_id` がログイン中のユーザーの ID） | `ReviewPolicy` の `update`・`delete` | F-12・F-13 |

- 編集画面（SC-04・SC-09）の表示と、更新の送信は、どちらも `update` で判定する。
- 判定はコントローラーの `$this->authorize()` で行う（要件「Policy」）。ビューの `@can` はボタンを出し分けるだけで、URL を直接入力したときは止められないため、サーバー側でも必ず判定する。

### ×のときの動き

| 区分と機能                          | 動き                                                                 | 確認事項 |
| ----------------------------------- | -------------------------------------------------------------------- | -------- |
| ゲストが F-03〜F-16・F-20 を使おうとした | ログイン画面へ移動する。画面を開こうとしたときは、ログイン後にその画面へ戻る | Q-10     |
| 会員が F-18・F-19 の画面を開いた      | 書籍一覧（`/`）へ移動する                                             | Q-08     |
| 会員が △ の条件を満たさない         | 403 エラー（Laravel 標準のエラー画面）                               | Q-47     |

## 補足

| ID          | 補足                                                                                                     |
| ----------- | -------------------------------------------------------------------------------------------------------- |
| F-02        | ゲストにも開けるが、お気に入り・いいね・レビュー投稿の操作は、ログイン画面へのリンクに置き換わる（`docs/screen-items.md`） |
| F-10        | 権限とは別に、書籍が紐付いているジャンルは削除できない（Q-17）。これは権限ではなく業務ルールのため、表では ○ にしている |
| F-16        | 表示するのはログイン中のユーザー自身のお気に入りだけ。ほかのユーザーのお気に入り一覧を開く URL は無い         |
| F-21〜F-25  | 基本機能では、誰でもどの書籍でも更新・削除できる。★応用機能で、書き込み系（F-23〜F-25）に Sanctum のトークン認証と、F-24・F-25 に `BookPolicy`（作成者のみ）を付ける（要件「APIエンドポイント一覧」の認証（応用）列） |

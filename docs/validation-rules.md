# バリデーションルール（想定）

具体的なバリデーションルールをまとめたもの。どれもまだ想定で、各ルールは `docs/questions.md` の確認事項（Q-xx）で確認中。
状態は `docs/questions.md` の状態欄を見る。

- 方針は `docs/requirements.md` の「バリデーション方針」に書かれている。このファイルは、その方針をもとに設計した具体的なルール。
- 範囲は基本機能のみ。★応用機能（`published_date` の nullable 化、Sanctum 導入後の登録者IDの見直し、読書計画）は含めない。
- 「Laravel のルール」列は実装するときのルールの案。

## ログイン（Fortify）

Fortify 本体の `LoginRequest` がチェックする。ルールは Fortify の初期値のまま使う。

| 項目           | 入力名     | ルール（想定） | Laravel のルール       | 要件の方針     | 確認事項 |
| -------------- | ---------- | -------------- | ---------------------- | -------------- | -------- |
| メールアドレス | `email`    | 必須           | `required`, `string`   | 必須チェック   | Q-42     |
| パスワード     | `password` | 必須           | `required`, `string`   | 必須チェック   | Q-42     |

メールアドレスとパスワードが合わないときのメッセージは `auth.failed`、ログイン回数の制限にかかったときは `auth.throttle` を使う。

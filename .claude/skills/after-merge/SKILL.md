# マージ後の片付け

状態を確かめる → **マージされたかを確かめる** → main を最新にする → その会話のブランチを消す → 残っているブランチを報告する、の順に進める。途中で問題が出たら、そこで止まって報告する。

「マージした」と言われても、そのまま信じない。マージされていないブランチを消すと、コミットがローカルから無くなる（リモートに残っていれば戻せるが、無ければ失う）。手順 2 の確認が取れるまで、ブランチの切り替えも削除もしない。

## 1. 状態を確かめる

```bash
git status -s
git branch --show-current
```

- 未コミットの変更があれば、`git checkout` の前に止まって、変更の内容を伝えて聞く。別の作業の途中かもしれず、切り替えると混ざるため
- 消す対象は、**この会話で作ったブランチ**。会話の中で `/start` やブランチ作成で切ったブランチを指す。対象がわからないときは、消さずに聞く

## 2. マージされたかを確かめる

対象のブランチについて、次の 2 つを**両方**確かめる。

```bash
gh pr list --head <ブランチ名> --state all --json number,state,mergedAt
git fetch origin
git merge-base --is-ancestor <ブランチ名> origin/main && echo "main に入っている" || echo "main に入っていない"
```

| 確かめること | 通る条件 |
| --- | --- |
| PR の状態 | `state` が `MERGED` で、`mergedAt` に日時がある |
| コミット | ブランチの先頭のコミットが、`origin/main` に含まれる（「main に入っている」と出る） |

- 同じブランチの PR が複数あるとき（閉じた PR と、出し直した PR など）は、`MERGED` のものを見る。`MERGED` が 1 つも無ければ、通らない
- どちらかが通らなければ、**ここで止まる**。ブランチの切り替えも、削除も、pull もしない。PR の状態（`OPEN` / `CLOSED`）と、ブランチの先頭のコミットを伝えて、ユーザーに確かめてもらう
- PR が見つからない（PR を出していない）ときも、止まって聞く
- PR は `MERGED` なのに、コミットが `origin/main` に含まれないときは、スカッシュマージやリベースマージの可能性がある。強制削除（`-D`）はせず、状況を伝えて聞く（このリポジトリは、普通のマージで取り込むため、含まれるのが通常）

## 3. main を最新にする

```bash
git checkout main
git pull origin main
```

pull が失敗したら、そのまま進めずに結果を伝える。

## 4. この会話のブランチを消す

消す前に、`main` に入っていることを、もう一度確かめる。

```bash
git merge-base --is-ancestor <ブランチ名> main && echo "main に入っている" || echo "main に入っていない"
```

「main に入っていない」と出たら、消さずに止まって報告する。

```bash
git branch -d <ブランチ名>
```

- **ローカルだけ**を消す。`git push origin --delete` などでリモートのブランチは消さない。「リモートも消して」とはっきり言われたときだけ行う
- `-D`（強制削除）は使わない。`-d` が失敗したら、消さずに止まって報告する
- `-d` が成功しても、`not yet merged to HEAD` という警告が出たら、`main` にマージされていないということ。消してしまったことを含めて、正直に報告する（コミットは、消す前のコミットから戻せる）
- 消したブランチ名と、消す前のコミット（`was 5f7146c` の部分）を伝える

## 5. 残っているブランチを報告する

```bash
git branch
git branch -r
```

この会話のブランチ以外に、残っているブランチを一覧で伝える。消すのは、頼まれてからにする。

- ローカルに残っているもの
- リモートに残っているもの（`origin/main` と `origin/HEAD` は除く）。この会話のブランチも、リモートに残っていればここに含める

## 6. 報告する

次を伝えて、止まる。

- マージを確かめた結果（PR の番号、`MERGED` の日時、`main` に入っていること）
- `main` を最新にしたこと
- 消したブランチ名
- 残っているブランチ（ローカル・リモート）
- 対応するイシューが閉じているか（`gh issue view <番号>`。イシューが無い作業なら省く）

次の作業の着手は `start` skill の役割なので、頼まれるまで始めない。

# マージ後の片付け

状態を確かめる → main を最新にする → その会話のブランチを消す → 残っているブランチを報告する、の順に進める。途中で問題が出たら、そこで止まって報告する。

## 1. 状態を確かめる

```bash
git status -s
git branch --show-current
```

- 未コミットの変更があれば、`git checkout` の前に止まって、変更の内容を伝えて聞く。別の作業の途中かもしれず、切り替えると混ざるため
- 消す対象は、**この会話で作ったブランチ**。会話の中で `/start` やブランチ作成で切ったブランチを指す。対象がわからないときは、消さずに聞く

## 2. main を最新にする

```bash
git checkout main
git pull origin main
```

pull が失敗したら、そのまま進めずに結果を伝える。

## 3. この会話のブランチを消す

```bash
git branch -d <ブランチ名>
```

- **ローカルだけ**を消す。`git push origin --delete` などでリモートのブランチは消さない。「リモートも消して」とはっきり言われたときだけ行う
- `-D`（強制削除）は使わない。`-d` が「マージされていない」と失敗したら、マージが取り込まれていないか、別のブランチを指している。消さずに止まって報告する
- 消したブランチ名と、消す前のコミット（`was 5f7146c` の部分）を伝える

## 4. 残っているブランチを報告する

```bash
git branch
git branch -r
```

この会話のブランチ以外に、残っているブランチを一覧で伝える。消すのは、頼まれてからにする。

- ローカルに残っているもの
- リモートに残っているもの（`origin/main` と `origin/HEAD` は除く）。この会話のブランチも、リモートに残っていればここに含める

## 5. 報告する

次を伝えて、止まる。

- `main` を最新にしたこと
- 消したブランチ名
- 残っているブランチ（ローカル・リモート）
- 対応するイシューが閉じているか（`gh issue view <番号>`。イシューが無い作業なら省く）

次の作業の着手は `start` skill の役割なので、頼まれるまで始めない。
